# APPARENTLY.
## Product Vision + MVP Build Brief

**Working title:** Apparently.  
**Core idea:** A playful social identity app where tiny daily questions, longer quizzes, world voting, comparison, and an evolving avatar gradually build a living picture of who you are.

**Tagline directions**
- *Let's see what that says about you.*
- *What does the world think — and where do you fit?*
- *Answer. Compare. Apparently, that's you.*

---

# 1. THE PRODUCT IN ONE SENTENCE

Apparently is a mobile-first social quiz game where users answer irresistible questions, instantly see how the world voted, discover how common or uncommon their answers are, compare with friends, and watch a personalized avatar evolve as patterns emerge across hundreds of answers.

This should **not** feel like a traditional quiz website.

It should feel like:

**TikTok dopamine + Love Island voting + BuzzFeed personality quizzes + Bitmoji/Tamagotchi progression + Spotify Wrapped shareability.**

The product should be simple enough to use for 15 seconds but interesting enough to keep someone tapping for 20 minutes.

---

# 2. PRIMARY PRODUCT LOOP

The core loop must be addictive before anything else is added.

1. User opens Apparently.
2. Sees one irresistible daily question.
3. Cannot see results before voting.
4. Votes.
5. Gets an immediate reveal:
   - percentage who chose the same answer
   - rarity/commonness
   - world distribution
   - a short funny "Apparently..." observation
6. Their personal profile changes slightly.
7. Progress toward an avatar unlock increases.
8. User can share the result or compare it with someone.
9. Another question/quiz is offered.
10. User comes back tomorrow to protect their streak.

**Golden rule:** Every completed interaction should create another reason to tap.

---

# 3. VISUAL DIRECTION

The first mockup's simplicity and pull are right, but the default product should be **lighter and warmer than the dark concept**.

## Default Theme

- warm white / soft cream background
- near-black charcoal text
- electric pink as primary interaction color
- violet, coral, orange, lilac, sky and gold as secondary accents
- large bold typography
- rounded cards
- lots of breathing room
- minimal navigation
- playful motion
- glossy highlights only where they increase reward/dopamine

Avoid:
- corporate SaaS dashboard styling
- clutter
- excessive gradients
- too many tiny stats
- clinical personality-test language
- childish cartoon styling
- making every screen dark

Dark mode can exist later, but it should not define the brand.

## Voice

Apparently should feel witty, observant, slightly shady, inclusive, playful, confident, never cruel, and never clinical.

Example:

> Apparently, you love spontaneity as long as it was discussed three business days in advance.

# 8. COMMONALITY

Signature Apparently metric.

### Your Commonality
**37%**

Meaning: the user tends to choose the most common answer about 37% of the time.

Possible labels:
- 0–20% — Wild Card
- 21–40% — Uncommon
- 41–60% — Somewhere in the Middle
- 61–80% — Crowd Compatible
- 81–100% — Human Consensus

Also show:
- rarest answer ever
- most universally agreed answer
- answers under 10%
- answers over 80%
- category-specific commonality

Examples:

Love — 71%  
Food — 46%  
Friendship — 29%  
Money — 21%  
Parenting — 58%

# 9. THE AVATAR

The avatar is not simply created by the user.

**Apparently builds the personality layer.**

The user can choose basic representation such as appearance, but personality objects, aura, accessories, environment, badges and visual evolution are earned from answer patterns.

The system should never infer sensitive identity traits from answers.

# 17. TECHNICAL STRATEGY

## Build APP + WEBSITE together

Do **not** build a separate web codebase first.

Recommended frontend:

### Expo + React Native + TypeScript + Expo Router

Targets:
- iOS
- Android
- Web

Use one shared codebase wherever practical.

Benefits:
- app-first product
- fast iPhone testing
- Android from the same project
- website from the same project
- shared design system
- shared quiz/reveal/profile logic

## Backend

Recommended starting option:

### Supabase
- Postgres database
- authentication
- realtime support
- storage
- server functions as needed

Firebase is a reasonable alternative.

A relational backend is useful because Apparently will have users, questions, answer options, votes, traits, cohorts, comparisons, quizzes, streaks and avatar unlocks.

## Native Builds

# 19. DATA / PRIVACY RULES

1. Never fake vote counts.
2. Never fake "world" percentages.
3. Show response count while sample size is small.
4. Do not expose demographic segment results below a safe minimum cohort size.
5. Do not collect precise location when broad region is enough.
6. Allow account deletion and data export.
7. Avoid sensitive personality inference.
8. Phrase traits as entertainment and observable answer patterns.
9. Do not make mental-health, medical, sexuality, political, religious or other sensitive-identity predictions from quiz behavior.
10. Use age-appropriate privacy defaults for minors.
